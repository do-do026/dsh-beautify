## 2. 正确的路线：bundle 包（不是动态插件）

### 2.1 包长什么样

```
beautify-plugin/
  package.json        ← 见下
  cordis.patch.yml    ← - insert: [{ id: dsh-beautify, name: '@local/dsh-beautify' }]
  index.js            ← 宿主半边，现在是个空壳：export function apply() {}
  client.js           ← 全部功能都在这（~1900 行）
```

`package.json` 的关键字段：

```json
{
  "exports": { ".": "./index.js", "./client": "./client.js" },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "immediately": true,
                "inject": ["@deepseek-ai/dsh-client-ui-conversation"] }
  }
}
```

客户端半边是个 CJS 工厂：

```js
window.__ModuleLoader__.load({
  id: '@local/dsh-beautify',
  factory(require) {
    const React = require('react');
    const h = React.createElement;
    return { inject: ['slots', 'theme', 'sidebarRightTabs'], apply(ctx) { … } };
  },
});
```

### 2.2 装进 profile

profile 的 `package.json` 里有 `"@local/dsh-beautify": "link:D:/dsh工作区/beautify-plugin"`。
因为走的是 `link:`，**改文件即时生效**，重装没必要。
用 `plugin_manager` 工具：`list_bundles` / `set_bundle` / `install_bundle`。

- 重复 `install_bundle` 会返回 `{"code":"ambiguous-install"}`，**无害**，说明它已经装过了。
- **`set_bundle` 启用/禁用是热生效的**，返回 `application: "applied"` 就成了。

### 2.3 迭代循环（这是整个方案的价值所在）

```
改 client.js 存盘  →  客户端自己重新注册  →  屏幕上就变了
```

**不用重装、不用刷新页面、不用重启应用。** 一轮几秒钟。

**唯一的例外：`package.json`。** 它是启动时读的，改了要重启 —— 而且它是最容易把应用搞挂的地方，见第 3 节。

### 2.4 没有浏览器怎么验

`_ref\preview.cjs` 是个无头测试台：桩掉 `window` / `React` / `document` / `Image`，
把 `client.js` 跑起来，打印**注册了哪些插槽**、**发了哪些 theme token**、**生成了什么 CSS**，
并且**真的调用各组件**渲染一遍（组件里抛错会在这里炸出来）。

```
node _ref\preview.cjs glass=true                 # 打开水玻璃
node _ref\preview.cjs 'cardPortrait=data:...' expressions=7
node _ref\preview.cjs noservice=true             # 服务缺失的降级路径
```

参数用 `key=value`，**不要传 JSON** —— PowerShell 会把里面的引号吃掉。

**改完必须跑：** `node --check client.js` + `node _ref\preview.cjs`。

## 3. ⚠️ 两个 inject —— 这里翻过一次车，整个应用打不开

DSH 客户端插件里有**两个同名叫 inject 但完全不同的东西**。

| | 在哪 | 内容 | 行为 |
|---|---|---|---|
| **A. 包依赖清单** | `package.json` 的 `dsh.client.inject` | **包名**数组 | 加载器**启动时校验**，解析不到 → **整个 bundle 拒绝加载** |
| **B. cordis 服务声明** | `return { inject: [...] }` | **服务名**数组 | cordis **等**服务就绪，**不会失败** |

### 事故经过（2026-09-28）

往 A 里加了一行 `"@deepseek-ai/dsh-client-ui-sidebar-right"`：

1. 客户端热重载立刻失败 → **界面退回全白原生样式**
2. 重启 → **应用整个打不开**，要在插件管理里「禁用所有第三方插件」才进得去

原因：profile 是 `link:` 安装的，它的 `node_modules` 里没有 DSH 内置包，A 里写包名解析不到。

### 所以

- **想用 `ctx` 上的某个服务，只能改 B。**
- **A 不要动。** 真要动，先让用户单独测一次启动。
- B 里**没声明的服务，读取时直接抛错**：`cannot get property "X" without inject` ——
  不是返回 `undefined`，所以「先 `if` 检查再决定」这种防御写法**根本走不到判断那一步**。

### 出事了怎么救

1. 插件管理里禁用 `@local/dsh-beautify`（它只是**禁用**，源码和配置都不会丢）
2. 改回 `client.js` / `package.json`
3. `plugin_manager` → `set_bundle` 重新启用，看返回的 `application` 是不是 `applied`

### 排查手法（很有效，留着）

在插件自己的设置面板里渲染一行**自检**：把内部状态机（`pending` / `registered` / `no-service` /
`error:<原始报错>`）和「已声明的服务是否可用」直接打在屏幕上。
**比猜快得多** —— 这次就是靠它一眼看到那句 `cannot get property … without inject` 才定性的。

## 4. 可复用的官方钩子（都用上了）

### 4.1 主题令牌

`ctx.theme.overrideTokens(source, tokens)`，`tokens` 是 `Record<名字, { light, dark }>`。
**传裸字符串会抛错**，必须亮暗两套。返回释放函数。

**令牌一共 395 个，不是 14 个**（旧版这里也写错了）。几个关键发现：

| 令牌 | 作用 |
|---|---|
| `--dsw-alias-bg-base` | 主区域**和输入框共用**，分不开 |
| `--dsw-specific-sidebar-fill` | 侧栏填充（被画了**两遍**：列上一次、根上一次） |
| `--dsw-alias-bg-layer-1/2/3` | 只有小面积的表面用它，当大背景滑杆是死的 |
| `--dsw-specific-bubble` | 用户气泡底色 |
| `--dsw-specific-menu` / `--dsw-menu-surface-fill` | 菜单、浮层 |
| `--dsw-menu-backdrop-filter` | **官方水玻璃就是它**：`blur(40px) saturate(150%)` |
| `--dsw-mask-blur` | 弹窗遮罩的模糊，默认 `none` |
| `--dsw-elevation-stroke` | **所有浮层阴影的第一段** —— 改这一个变量就能给菜单/悬浮卡/弹窗/toast 全部加上沿高光，一个类名都不用点 |

### 4.2 DSH 自己就带水玻璃

`[data-platform=darwin]` 下有几条规则，那就是官方的配方，Windows 上没有：

```css
[data-platform=darwin] .ZTP-Xa_frame      { background: 0 0 }          /* 底板撤掉 */
[data-platform=darwin] .ZTP-Xa_sidebarCol { 渐变高光 + 打四折的淡填充 }
[data-platform=darwin] .n_2Q3W_root       { background: 0 0 }          /* 里层重复填充归零 */
```

本插件就是把这套搬到 Windows，再补一层 `backdrop-filter`。

### 4.3 插槽

| 插槽 | 用途 |
|---|---|
| `shell.overlay` | 框架级浮层。**背景图在 order -100（在应用后面），悬浮立绘在 order 10（在前面）** |
| `conversation.session.header.utilities` | 会话标题栏右侧 → waifu 开关 |
| `settings.section` | 设置左边菜单的一栏 → **「美化」和「角色卡」两栏** |
| `sidebar.right.pane.tab` | 右栏正文，`key` = 类型 id |

### 4.4 右栏标签

```js
ctx.effect(() => ctx.sidebarRightTabs.register({
  id: CARD_ID, kind: CARD_KIND, priority: 'extension',
  title: () => '角色卡',                                  // 函数
  guide: [{ id: 'card', order: 30, title: () => '角色卡',
            description: () => '立绘、表情和设定', icon: CardIcon }],
}));
ctx.slots.inject('sidebar.right.pane.tab', () =>
  ctx.slots.register({ name: 'sidebar.right.pane.tab', key: CARD_ID }, CharacterCard));
```

`guide` 的入口会自己出现在右栏「工作区文件 / 新建终端 / 浏览器」那个列表里。
`icon` 可以给一个自写的 SVG 组件（**不要去 require primitives 包拿图标**，多一个依赖就多一个失败点）。

## 7. 已知坑

- **两个 inject** —— 见第 3 节，这是最贵的一条
- **不要用 PowerShell 改含中文的文件。** `Get-Content -Raw` 会按系统 ANSI 代码页（cp936）解码
  UTF-8，`Set-Content -Encoding utf8` 再写回，全部中文变乱码且 `node --check` 失败。
  **用 `edit` / `write` 工具，或 node 的 `fs.writeFileSync`。**
  真发生了可以无损还原：`ReadAllText(UTF8)` → 用 cp936 `GetBytes` → `WriteAllBytes`（.NET 的当前目录
  和 pwsh 的 `cd` 不是一回事，**必须传绝对路径**）；反向之后每个损坏点会剩成 `\uFFFD` + `?` 两个字符，
  再逐处补回。</br>**只靠 `\uFFFD` 计数为 0 不算验过** —— 被吃掉的字节也可能恰好是个合法 ASCII，
  形成**不报错的静默错误**（那次 71 处里就有一处把「压到 70%」补成了「压到770%」，是逐行肉眼比对抓出来的）。
- **绝不做 React 节点的 DOM 手术**。全部靠 CSS 覆盖 + 官方令牌，失败是静默的、不破坏渲染。
- `cordis_inspect_query`（platform=client）**会等页面应答**，页面忙就挂着 —— 改从 asar 里直接读。
- `conversation.chat.node` 的 key 被官方占满，注册同一 key = **替换**官方渲染器
  （`replaceRisk: shadows-shipped-ui`）。替换 `assistant-step` 要自己负责 markdown 渲染，很重，别碰。
- `desktop/cordis.patch.yml` **会被桌面端 UI 改写**（改设置就写它），往里加行要小心被覆盖。
- **DSH 是明确禁止 mock 预览的**，而且这个环境里也没有浏览器控制 —— 视觉只能靠用户截图确认。
  所以：**每次改完都要跑 `node --check` + `preview.cjs`**，把能自动验的都验掉。
